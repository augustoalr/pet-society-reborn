   - Interfaz `Transaction`:
     - `readonly id: string`
     - `readonly type: TransactionType`

   - Interfaz `TransactionResult`:
     - `readonly success: boolean`

     - `readonly error?: EconomyErrorCode`
     - `readonly transaction?: Transaction`
     - `readonly transactions?: readonly Transaction[]` (para operaciones multidivisa atómicas)
3. Implementa las funciones puras y el servicio del dominio en `src/domain/economy/walletLogic.ts`:
   - Validación estricta de montos positivos:
     `validateAmount(amount: number): boolean`
     - Debe ser número finito, entero, > 0 y no NaN.
   - Función pura de crédito:
     `creditCurrency(wallet: Wallet, currency: CurrencyType, amount: number, description?: string): TransactionResult`
     - Valida `validateAmount(amount)`. Si es inválido, retorna `{ success: false, wallet, error: 'INVALID_AMOUNT' }`.
     - Previene overflow numérico (`Number.MAX_SAFE_INTEGER`). Si excede, retorna `{ success: false, wallet, error: 'OVERFLOW_LIMIT' }`.
     - Retorna nuevo Wallet inmutable con saldo incrementado y `transaction` registrada.
   - Función pura de débito:
     `debitCurrency(wallet: Wallet, currency: CurrencyType, amount: number, description?: string): TransactionResult`
     - Valida `validateAmount(amount)` (falla con `INVALID_AMOUNT` si <= 0 o inválido).
     - Valida saldo suficiente (`wallet[currency] >= amount`). Si no alcanza, retorna `{ success: false, wallet, error: 'INSUFFICIENT_FUNDS' }`.
     - Si alcanza, retorna nuevo Wallet con saldo restado y `transaction`.
   - Función de compra compuesta (Transaction Checker & Compra atómica):
     `canAfford(wallet: Wallet, cost: { coins?: number; cash?: number }): boolean`
     `purchase(wallet: Wallet, cost: { coins?: number; cash?: number }, description?: string): TransactionResult`
     - **Regla de costos defensiva:** Los costos `cost.coins` y `cost.cash` deben ser números enteros `>= 0` o `undefined`. Si se envía cualquier valor negativo (`< 0`), `NaN` o no finito, se rechaza la transacción de inmediato con `INVALID_AMOUNT` para erradicar exploits de costo negativo.
     - Si no se especifica costo o ambos son 0, no hay débito y retorna éxito.
     - Valida que `wallet.coins >= (cost.coins ?? 0)` y `wallet.cash >= (cost.cash ?? 0)`. Si alguno falta, retorna `{ success: false, wallet, error: 'INSUFFICIENT_FUNDS' }` dejando el wallet intacto (atomicidad total).
     - Si ambos son suficientes, debita las cantidades correspondientes y retorna el nuevo `wallet` junto con el array `transactions` con un registro por cada divisa debitada.
